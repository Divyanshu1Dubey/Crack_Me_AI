## 2. Fixture migration (CMS, NEET PG, INI-CET) — verified safe

### What moved

| Before | After |
|---|---|
| `backend/questions_fixture.json` (5.3 MB, all exam tracks mixed) | `backend/fixtures/cms_fixture.json` (renamed) + `neet_pg_fixture.json` + `inicet_fixture.json` |
| Loading via `manage.py loaddata questions_fixture.json` | Loading via `manage.py load_exam_fixture {cms\|neet_pg\|inicet}` |
| Image references hard-coded as raw URLs | Inline `[[img:foo.png]]` tokens → rewritten to `/media/fixtures/images/<exam>/foo.png` at load time |

### Verification I ran

**Counts (parsed with `python -X utf8` so Windows cp1252 didn't trip the JSON decode):**
- `cms_fixture.json` → 5 subjects + 1,918 topics + **1,920 questions** (same as before).
- `inicet_fixture.json` → ExamTrack + 16 subjects + 16 topics + 3 demo questions + doc-comment rows (loader uses `_doc/_note/_section` keys to ignore them).
- `neet_pg_fixture.json` → ExamTrack + 19 subjects + 22 topics + 3 demo questions.
- Subjects 1-5 in CMS = General Medicine / Pediatrics / Surgery / OBGY / PSM (canonical). Question exam_type is `None` on all rows → migration 0026 sets default `'cms'` so the field is consistent.

### Modified files affected by this split
- `backend/questions/views.py:62-65` — `_ensure_question_bank_loaded` now tries `fixtures/cms_fixture.json` first, falls back to the old path. Safe.
- `backend/test_all.py` — three test paths updated with the same back-compat pattern. Safe.
- `backend/questions/management/commands/fix_mojibake.py` — defaults `--fixture` to the new path; old path still accepted. Safe.
- `backend/crack_cms/settings.py:101` — registers `material_importer` in `INSTALLED_APPS`.

### New `load_exam_fixture` capability surface
```
python manage.py load_exam_fixture {cms|neet_pg|inicet|ini_cet} \
    [--replace] [--dry-run] [--images-dir PATH]
```
- `--dry-run` validates JSON without writing (great for CI).
- `--replace` deletes existing Subject/Topic for the exam_type before reloading.
- Image tokens on missing PNGs are left in place rather than dropped (so QA flags them).

### Risks found in the migration
- **None** — the split is purely organizational + image-token-based. The only CMS-side action was renaming + adding the loader helper. All data preserved.

## 5. Material_importer — new app review

See [`docs/MATERIAL_IMPORTER_AUDIT.md`](MATERIAL_IMPORTER_AUDIT.md) for the full architecture, stage-by-stage details, and bug list. Highlights:

- **Format agnostic**: DOCX (full pipeline), PDF (lazy), PPTX (lazy), TXT/MD (lazy). PDF/PPTX/Text adapters gracefully degrade if libraries missing.
- **Two extraction strategies** for DOCX — `ClassicMCQExtractor` (free-text MCQs) and `BoxedMCQExtractor` (Word tables) — both written to handle real Meduraa authoring templates.
- **Two-stage dedup** — exact hash → 6-gram shingle. Threshold 0.85 Jaccard. Inverted index keeps it fast even on an 8 K-bank.
- **Idempotent mock-test builder** with one high-risk bug (see §6.4 of MATERIAL_IMPORTER_AUDIT.md): `update_or_create` with `is_published=False` in defaults silently un-publishes live tests on rebuild.
- **QC report tooling is in place**: `manage.py qa_report --batch 13` produces a JSON file that already documents Batch #13 results.
- **Test coverage: zero** — biggest gap on this new app.
