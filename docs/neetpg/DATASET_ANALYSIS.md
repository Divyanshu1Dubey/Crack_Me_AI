## 4. Detected structural patterns

Across the dataset we expect (subject to per-PDF analysis):

- **NEET PG year papers** — typically 200 questions, single-best answer, with solutions/answer key section at the end. Mostly digital text, occasionally with figures embedded as raster images on a few pages.
- **Subject-wise PYQ bundles** — variable length, often 200–1000+ questions, may span multiple years (NEET PG + INI-CET + AIIMS PG + state PSC), mixed into a single subject-wise document. Frequently scanned or hybrid. Many questions are image-dependent (histology, radiology, instruments).
- **Answer key conventions:**
  - Inline: "Ans: A" / "Answer: (b)"
  - Trailing "Answer Key" section per year
  - Footer with answer codes
  - Coaching-style: bold-italic markers
- **Image conventions:**
  - ECGs as raster (often monochrome, low DPI)
  - X-rays/CT as raster with high detail
  - Histology photos
  - Gross specimen photos
  - Flowcharts as scanned diagrams
  - Sometimes the image is essential — the question text alone is unanswerable.

## 5. What we extract per PDF

For each PDF the import pipeline writes to disk:

```
backend/importers/neetpg/_output/
  raw/
    <sha256_short>__<filename>.jsonl       # raw page text + page images index
  pages/
    <sha256_short>/p<NNNN>.png            # 200 DPI page renders for OCR fallback
  images/
    <sha256_short>/p<NNNN>_i<NN>.<ext>    # extracted embedded images
  parsed/
    <sha256_short>.questions.jsonl        # parsed questions with options/answer/explanation
  manifest.json                            # resumable, idempotent state
```

Every artefact is **hash-stamped** so re-runs are deterministic and duplicates collapse.

## 6. Quality expectations & known risks

| Risk | Mitigation |
|---|---|
| Watermarks confuse OCR | Detect watermark regions, mask before OCR |
| Rotated scans | Auto-deskew via OpenCV minAreaRect on the page render |
| Multi-column layouts | Two-column detection via median x-coordinate clustering of text blocks |
| Header/footer noise | Strip patterns like "Page 12 of 230", "Marrow Recall 2024", etc. via header/footer regex dictionary |
| Poor contrast scans | Adaptive threshold + sharpening before OCR |
| Missing options (only 3 instead of 4) | Flag as quality issue; do not auto-fix |
| Multi-correct ("All of the above except") | Tag with `multi_correct=True` and capture all correct option labels |
| Assertion-Reason format | Detect and store as `question_type='assertion_reason'` with both halves preserved |
| Image-only stem ("What is the diagnosis?") | Always render at high DPI; never lose the image from the question record |
